# Question 5 — Operating Systems, Terminals, and Shells

**Format:** Short Answer

---

> Answer in your own words, 1-3 sentences each. Writing it yourself is the point.


**(a)** What is a **kernel**, in plain language? (One or two sentences. No textbook definition copied in; explain it as you understand it.)

**Answer:**

Basically the kernel is the middleman between our apps and your actual computer hardware (e.g. CPU, memory, etc.). Whenever a program needs to do something like save a file or use more RAM, instead of touching the hardware directly, it goes through the kernel, which handles the request and keeps everything from stepping on each other.

---

**(b)** A classmate says:

> "I installed WSL, so now I have two completely separate operating systems, Windows and Linux, running side by side, each totally independent."

Is this accurate? Briefly explain why or why not.

**Answer:**
WSL doesn't give you two totally separate machines running independently. It's more like Linux is running in a lightweight environment that's plugged directly into Windows, so they can share files and resources between them. It's not isolated the way a real dual-boot setup or a fully separate VM would be.

---

**(c)** Explain the difference between a **terminal (emulator)** and a **shell**, and give one example of each.

**Answer:**
The terminal is just the window users can type into, like the Terminal app or the one built into VS Code. The shell is the actual program running inside that window that reads what I type and does something with it — mine is zsh, based on what echo $SHELL showed me. Other examples would be bash or PowerShell.
